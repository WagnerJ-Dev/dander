# __DISPLAY_NAME__ connector for Dander

Generic REST connector-plugin scaffold generated by
[`dander plugins scaffold`](https://github.com/harrisonoconnorhover/dander).

> **Before publishing:** replace the example API contract, fields, tests, package links, and
> support claims with behavior you have actually validated. Never commit credentials or real data.

## Develop

1. Edit `src/__PACKAGE_NAME__/templates/__PLUGIN_ID__.example.yaml` with the read-only API,
   pagination, and declared raw schema you need.
2. Extend `__SOURCE_CLASS__` only when the generic REST runtime cannot express the provider.
3. Replace the synthetic descriptor fields and add realistic fixtures and failure tests.
4. Run:

```console
uv sync --extra dev
uv run ruff check .
uv run ruff format --check .
uv run mypy src tests
uv run pytest
uv build
```

`uv sync` creates `uv.lock`; commit that lockfile so the generated CI can install with `--frozen`.

## Install in Dander

After publishing an exact plugin version, add it to `dander.yaml`:

```yaml
plugins:
  __PLUGIN_ID__:
    distribution: __DISTRIBUTION_NAME__
    version: 0.1.0
```

Then run `dander plugins install` and copy the example connector into the Dander project's
`connectors/` directory.

## Publish

The generated workflow builds only a tag exactly matching `v<package-version>` and uses PyPI
trusted publishing through a GitHub environment named `pypi`. Create the repository and PyPI
project yourself, configure that trusted publisher, require review on the environment if desired,
and review the complete tagged diff before manually running the workflow.
